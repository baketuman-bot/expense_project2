仕組み

固定資産台帳（Web）と Access MDB（FDATA001.MDB / fpack の基幹データ）は、 リアルタイムには繋がっていません。以下の手動トリガー式の片方向処理を、担当者が sync_assets.bat を実行するたびに順番に行います。 

[Django (Web)] ──表示/編集──> MySQL T_ASSETS（即時反映）
      │                        + 同期キュー（変更内容を記録）
      │
[Windows側 sync_assets.bat] ← 担当者が手動実行
      ├─ ① Push: キュー(未送信) → 本物MDB tbl固定資産 へ UPDATE/INSERT
      └─ ② Pull: 本物MDB v_assets → MySQL T_ASSETS へ upsert
  • Web画面で編集・新規登録すると、MySQL側にはすぐ反映されますが、変更されたフィールドだけが 「同期キュー」に未送信（pending）として記録されます。MDB本体にはこの時点ではまだ書き込まれません。
  • ① Push: 未送信キューを1件ずつ本物のMDBへ反映します。成功した行から順に「送信済」になります。
  • ② Pull: MDB側の最新データをMySQLへ取り込みます。ただし、 まだ未送信・エラーのキューが残っている資産NOは、Web側の変更を上書きしないためPullの対象から除外されます。
実行手順
  1. fpack が稼働している Windows 機にログインする。
  2. デスクトップの sync_assets.bat をダブルクリックする。
  3. 通常実行は Push → Pull の順に自動で行われます。処理結果（成功/失敗件数）はコンソールと sync_assets.log に記録されます。
  4. エラー状態のキューを再送信したい場合はコマンドプロンプトから python sync_assets.py --retry-errors を実行してください。
  5. 書き込みを行わず内容だけ確認したい場合は python sync_assets.py --dry-run を実行してください。
注意事項
  • 同期中は fpack 側でデータを編集しないでください。Pushの途中でMDBが更新されると 整合性が崩れるおそれがあります。
  • MDBへの書き込み前に自動でバックアップが作成されますが、スクリプトを止める・強制終了するなど 異常終了させないでください。Push処理はMDBへのコミット後にキューを「送信済」にするため、 処理を中断すると MySQL とMDBの状態がズレる可能性があります。
  • 同期は手動実行のみです（スケジューラ登録なし・Webからの自動起動なし）。 Web側で編集した内容は、次回 sync_assets.bat を実行するまでMDBには反映されません。
  • 読み取り専用フィールド（部門名・科目名など、マスタ結合由来の8項目）はWeb編集フォームで入力できず、 Push対象にもなりません。
  • エラーになったキューは自動では消えません。同期キュー一覧 でエラー内容を確認し、必要に応じて --retry-errors で再送信してください。
  • セットアップ手順・接続情報の詳細は deploy/windows_sync/README.md を参照してください。
