GroupSessionデータコンバートについて

マスタ設定へ戻る
このコンバートはWeb画面から起動することはできません。 実際の処理は、経理ファイルサーバーへアクセスできる Windows 機の deploy/gs2db_sync/sync_gs2db.bat を、担当者が手動でダブルクリックして実行します。 このページは仕組みと注意事項の案内のみを目的としています。

仕組み

現在も別システムとして並行運用しているグループウェア「GroupSession」のH2データベースファイル （gs2db.h2.db、レガシーPageStore形式）から、稟議データ・ユーザー・組織情報を抽出し、MySQLの GS_RINGI / GS_USR / GS_GROUP / GS_BELONG / GS_POSITION テーブルへ参照専用データとして取り込みます。 パスワード不明でも読める「フォレンジック復元」方式（org.h2.tools.Recover）を使うため、 GroupSession側のDB認証情報は不要です。 

\\172.16.100.15\keirifile\...\gs2db\gs2db.h2.db
      │  ① Windows robocopy（WSLからは共有へ直接アクセス不可のため中継）
      ▼
deploy/gs2db_sync/work/gs2db_src.h2.db
      │  ② extract_gs2db.py（WSL / H2フォレンジック復元）
      ▼
deploy/gs2db_sync/csv/*.csv
      │  ③ manage.py import_gs2db（WSL / upsert）
      ▼
MySQL GS_RINGI / GS_USR / GS_GROUP / GS_BELONG / GS_POSITION
  • ① 共有からのコピー: WSLからは経理ファイルサーバー共有へ直接アクセスできないため、 Windows側のrobocopyで作業用ディレクトリへ中継します。
  • ② CSV抽出: extract_gs2db.py がH2データベースファイルを解析し、 5テーブル分のCSVを再生成します。
  • ③ MySQL取込: import_gs2db 管理コマンドが CSV を読み込み、 update_or_create による upsertのみで取り込みます （DELETE/TRUNCATEは一切行いません）。
実行手順

自動実行（通常はこちら）

  1. 経理ファイルサーバー共有へアクセスできる Windows 機にログインする。
  2. deploy/gs2db_sync/sync_gs2db.bat をダブルクリックする。
  3. 共有からのコピー → CSV抽出 → MySQL取込が自動で順に実行されます。 結果は sync_gs2db.log（batと同じディレクトリ）に記録されます。

手動実行（個別に確認したい場合）

# 1. gs2db.h2.db の最新コピーを用意する

# 2. CSV抽出
cd deploy/gs2db_sync
python3 extract_gs2db.py ../../tmp/gs2db.h2.db csv/

# 3. 件数・先頭数件を確認してから本実行
cd ../..
python manage.py import_gs2db deploy/gs2db_sync/csv/ --dry-run
python manage.py import_gs2db deploy/gs2db_sync/csv/
注意事項
  • 取り込みはupsertのみです。GS_*テーブルへのDELETE/TRUNCATEは一切行われません。
  • パスワードハッシュ（USR_PSWD）は取り込み対象外です。
  • H2ページストア内部にLOBとして保存されている大きなテキスト値（例: RNG_TEMPLATE.RTP_FORM）はテキスト解析だけでは復元できません。ただし今回の 取り込み対象5テーブルにはCLOB列を含まないため実害はありません。
  • 抽出元ファイル・CSV出力には実在従業員の氏名・社員番号等が含まれるため、 リポジトリには含めず（.gitignore対象）、取り扱いに注意してください。
  • gs2db.h2.dbの新しいコピーが提供されるたびに sync_gs2db.bat を 再実行すれば、GS_*テーブルが最新化されます。
  • セットアップ手順（Java・H2 jarの準備等）の詳細は deploy/gs2db_sync/README.md を参照してください。
