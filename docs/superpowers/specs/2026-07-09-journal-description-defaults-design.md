# 仕訳作成 摘要デフォルト値変更 設計書

## 背景・目的

仕訳作成画面（`/settings/settlement/journal/`）で明細ごとに借方・貸方の摘要を入力する際、現在自動セットされるデフォルト値の項目・並び順を、経理の運用に合わせて変更する。あわせて、摘要が長くなりすぎた場合に気づけるよう、40文字を超えたら警告表示を出す。

## 対象範囲

- `expenses/views.py` の `journal_detail_api`（views.py:5451〜）内、借方摘要 (`_def_desc_deb`) ・貸方摘要 (`_def_desc_cre`) のデフォルト値生成ロジック
- `expenses/templates/expenses/settlement_journal_entry.html` の借方摘要・貸方摘要入力欄まわりのJS/HTML

## 変更内容

### 1. 借方摘要のデフォルト値

構成要素（スペース区切り、空項目はスキップ）:

```
[旅費特例] 月/日 目的 精算者名 支払先 申請ID
```

- `旅費特例`: 勘定科目コードが `'670'`（旅費交通費）のときのみ先頭に追加する（既存の `raw_acd.strip() == '670'` 判定を流用）
- `月/日`: `content.date`（明細日付）を `M/D` 形式で使用（例: `7/8`）
- `目的`: `content.purpose`
- `精算者名`: 申請者名（`doc.man_number.user_name`、既存の `_applicant_name` 変数を流用）
- `支払先`: `content.shiharaisaki`
- `申請ID`: `doc.document_id`

### 2. 貸方摘要のデフォルト値

基本構成（スペース区切り、空項目はスキップ）:

```
月/日 目的 精算者名 支払先 申請ID
```

ただし `content.corpo_card == 2`（法人カード、既存の貸方科目判定と同じ条件）のときは精算者名を除外:

```
月/日 目的 支払先 申請ID
```

各項目の定義は借方と同じ。

### 3. 共通の後処理

既存同様、結合後の文字列は50文字（入力欄の `maxlength`）で切り詰める。これは今回の仕様変更の対象外で、現行動作を踏襲する。

### 4. 40文字超の警告バッジ

- 借方摘要 (`inp-jnl-desc-deb`) ・貸方摘要 (`inp-cre-desc`) それぞれの入力欄の隣に、既存の `.jnl-badge.jnl-badge-warn` スタイルを使った小バッジ「40文字以上」を追加する
- 初期状態は非表示 (`display:none`)
- 入力欄の `input` イベントで現在値の文字数を判定し、40文字を超えていれば表示、40文字以下なら非表示にする
- 明細読み込み時（デフォルト値または保存済み値を `.value` にセットした直後）にも同じ判定関数を呼び、初期状態を反映する
- サーバー側での判定・警告データの返却は不要（フロントのみで完結させる）

## 影響範囲・非対象

- 保存処理 (`journal_save`) や必須チェック (`required_checks`) には変更を加えない。40文字超は警告のみで保存をブロックしない。
- CSV出力・仕訳エクスポート側のロジックには影響しない（摘要の値自体は既存カラムをそのまま使う）。
- 分割行 (`split_from` あり) の摘要生成ロジックは対象外（分割行には貸方摘要フィールド自体が存在しないため）。

## テスト観点

- 勘定科目=670のとき、借方摘要の先頭に「旅費特例」が付与されること
- 勘定科目≠670のとき、「旅費特例」が付与されないこと
- 法人カード (`corpo_card == 2`) のとき、貸方摘要に精算者名が含まれないこと
- 法人カードでないとき、貸方摘要に精算者名が含まれること
- 各項目が空の場合（目的なし・支払先なし等）、余分なスペースが入らないこと
- 40文字を超える摘要を入力すると警告バッジが表示され、40文字以下に戻すと消えること
- 明細を切り替えたとき、デフォルト値・保存済み値それぞれに対して警告バッジの初期状態が正しく反映されること
